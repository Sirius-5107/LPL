# Data Dictionary — Day 1

---

## AccountType

| Value | Meaning |
|-------|---------|
| `taxable_brokerage` | Standard brokerage. Realised gains taxed at capital gains rates. Cost basis tracking required. |
| `traditional_ira` | Pre-tax contributions. All withdrawals taxed as ordinary income. No capital gains treatment. |
| `roth_ira` | After-tax contributions. Qualified withdrawals tax-free. No RMD. |
| `annuity` | Insurance contract. Tax treatment depends on contract type (fixed, variable, indexed). Gain taxed as ordinary income on withdrawal. |
| `unknown` | Account type not yet determined. Must be resolved before tax calculations. |

---

## LiquidityStatus

| Value | Meaning |
|-------|---------|
| `liquid` | Can be sold or redeemed at or near market value with standard settlement. |
| `partially_liquid` | Some portion can be liquidated; full liquidation may be restricted or complex. |
| `restricted` | Subject to surrender period, lockup, or penalty. Exit cost likely. |
| `illiquid` | Cannot be sold or transitioned in a standard advisor-driven transaction. Must be RETAINED. |

---

## CostBasisStatus

| Value | Meaning |
|-------|---------|
| `known` | `cost_basis` field is populated and reliable. |
| `unknown` | Cost basis was not provided. Must NOT be treated as zero. `MissingCostBasisError` raised if used in a calculation. |
| `inapplicable` | Cost basis concept does not apply to this holding (e.g., Traditional IRA — full withdrawal is ordinary income regardless of original contributions). |
| `partial` | Some tax lots have known basis; others do not. Cannot compute full gain/loss. |

---

## RateInterpretation (AnnuityTerms)

| Value | Meaning |
|-------|---------|
| `payout_rate` | The percentage of account balance distributed as income per year. |
| `guaranteed_interest_rate` | The annual crediting rate applied to the account balance. |
| `withdrawal_rate` | The maximum percentage that can be withdrawn per year without surrender charge. |
| `unresolved` | The dossier description has not been mapped to a specific economic concept. No income or growth calculation may proceed. |

---

## PortfolioLabel

| Value | Meaning |
|-------|---------|
| `CI` | Current Investment Portfolio — the client's existing holdings. |
| `PI` | Proposed Investment Portfolio — the advisor's recommended transition target. |
| `RI` | Independently Recommended Portfolio — a third alternative generated by the system. |

---

## ScenarioType

| Value | Meaning |
|-------|---------|
| `full_transition` | All transitionable CI holdings are moved to PI. |
| `partial_transition` | A subset of holdings is transitioned. |
| `staged_transition` | Transition occurs over multiple time periods. |
| `retain_ci` | No transition — CI is retained. Used as a baseline. |
| `independent_ri` | Transition to a system-generated portfolio rather than the advisor's PI. |

---

## TransitionAction

| Value | Meaning |
|-------|---------|
| `sell_all` | Liquidate the entire holding. Not valid for ILLIQUID holdings. |
| `sell_partial` | Liquidate a fraction of the holding. `fraction` field required. Not valid for ILLIQUID. |
| `retain` | Keep the holding unchanged in the portfolio. Valid for any liquidity status. |
| `convert` | Convert the holding, e.g., Traditional IRA → Roth IRA. Tax event. |
| `exchange` | In-kind or 1035 annuity exchange. Tax treatment depends on contract. |
| `deferred` | Transition planned for a future date. `staged_date` required. |
| `review` | Requires human review before action can be taken. |

## Key monetary fields

| Field | Type | Notes |
|-------|------|-------|
| `market_value` | `Decimal` | Current nominal USD market value. Always nominal unless otherwise labelled. |
| `cost_basis` | `Optional[Decimal]` | Original purchase cost in nominal USD. `None` = unknown. NEVER zero by default. |
| `expense_ratio` | `Optional[Decimal]` | Annual recurring cost as decimal fraction (e.g. `0.0075` = 0.75%). |
| `exit_cost_pct` | `Optional[Decimal]` | One-time exit cost as decimal fraction. |
| `entry_cost_pct` | `Optional[Decimal]` | One-time entry cost as decimal fraction. |

## New fields added in Day 2 validation hardening

### Holding.exchange_eligible

| Value | Meaning |
|-------|---------|
| `true` | Holding has been explicitly confirmed as eligible for an in-kind or 1035 exchange. |
| `false` | Exchange is explicitly not permitted for this holding. |
| `null` (default) | Eligibility is unknown. Do NOT assume eligible. Annuity exchanges require explicit confirmation. |

This field governs EXCHANGE instructions **only**. It does **not** authorize a SELL_ALL or SELL_PARTIAL — those require `sale_eligible=True`. The two fields are entirely independent.

For ANNUITY holdings: `exchange_eligible=True` signals explicit eligibility input only. It does **not** imply legal or economic suitability of a 1035 exchange.

### Holding.sale_eligible

| Value | Meaning |
|-------|---------|
| `true` | Holding has been explicitly approved for an ordinary sale (SELL_ALL or SELL_PARTIAL). |
| `false` | Sale is explicitly not permitted for this holding. |
| `null` (default) | Eligibility is unknown. For RESTRICTED holdings, unknown eligibility blocks the sale with a blocking ERROR. |

This field governs sale instructions **only** for RESTRICTED holdings. It does **not** authorize an EXCHANGE — that requires `exchange_eligible=True`. LIQUID holdings do not require this flag. The two fields are entirely independent and must never substitute for each other.

### TransitionInstruction.destination_account_id

| Field | Type | Meaning |
|-------|------|---------|
| `destination_account_id` | `Optional[str]` | For CONVERT instructions only: the account ID of the receiving account. Required and must resolve to a ROTH_IRA account for a valid IRA-to-Roth conversion. |

---

## Nominal vs Real

All monetary values in models are nominal (not adjusted for inflation) unless a field
name explicitly includes `_real`. Engine outputs carry both `_nominal` and `_real`
variants where applicable. Real values require an explicit `inflation_rate_annual`
input — they are never inferred.

## Gross vs Net performance

`annualised_gross_return_nominal` = return before fees.  
`annualised_net_return_nominal` = return after expense ratio deducted.  
These are never the same field. Net performance always requires an explicit expense
ratio input.
